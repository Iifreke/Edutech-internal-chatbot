Standard Operating Procedure (SOP)

Edutech Global AI Assistant (Skylar) Platform

Document Version: 1.0
Last Updated: May 2026
System: Edutech Global Internal AI Knowledge Base Assistant

1. Purpose and Scope

This Standard Operating Procedure (SOP) outlines the standardized protocols for managing, maintaining, and updating the Edutech Global AI Assistant. This covers accessing the Admin Dashboard, uploading knowledge base documents, handling escalated leads, and troubleshooting core system functionalities. The scope includes administrative users and system maintainers.

2. System Overview

  • Frontend Application: Next.js (React)
  • Backend Services: Next.js API Routes
  • Database & Vector Storage: Supabase (PostgreSQL with pgvector)
  • AI Inference: OpenRouter API (LLM Integration)
  • Brand Identity: Edutech Global (Primary Red: #D31E1E, Dark: #111111)

3. Accessing the Admin Dashboard

The Admin Dashboard is the central control hub for managing the AI Assistant's knowledge and monitoring interactions.

  1. Navigate to the deployed application URL and append /admin (e.g., https://yourdomain.com/admin).
  2. You will be prompted for an Admin Password. Enter the password configured in the ADMIN_PASSWORD environment variable.
  3. Upon successful authentication, you will have access to the Document Management and Lead Escalation panels.

4. Knowledge Base Management

4.1 Uploading Documents

To improve the AI's accuracy, you must provide it with up-to-date company documents.

  1. In the Admin Dashboard, locate the "Upload Document" section.
  2. Select the desired file (Supported formats: PDF, TXT, MD).
  3. Click Upload.
  4. The system will automatically extract the text, split it into semantic chunks, generate vector embeddings, and store them securely in Supabase. Wait for the success confirmation before leaving the page.

4.2 Managing Existing Documents

  • Viewing: The dashboard displays a list of all currently ingested documents.
  • Reprocessing: If a document's content needs to be re-embedded or if an error occurred during chunking, click the Reprocess button next to the document.
  • Deleting: To remove outdated knowledge, click Delete. This automatically purges associated vector chunks from the database to ensure the AI does not reference stale data.

5. Live Escalation and Lead Management

When the AI Assistant encounters a query it cannot resolve or when a user requests human intervention, the chat is escalated.

  1. Monitor the Conversation List in the Admin Dashboard. Escalated chats will be highlighted.
  2. The sidebar allows filtering leads by Global School. Ensure the "Babcock" university standardization is consistently applied when filtering.
  3. Click on an active escalated lead to view the chat history.
  4. Use the Live Admin Response System input field to send a manual reply. The system uses Supabase-polling to instantly deliver your response to the user's chat interface.

6. Scraping Web Content

The platform supports ingesting live web content into the knowledge base.

  1. Navigate to the Web Scraping section in the Admin Dashboard.
  2. Input the target URL.
  3. Execute the scrape. The system will retrieve the text, clean it, chunk it, and embed it similarly to a document upload. Ensure you only scrape authorized URLs.

7. Maintenance and Troubleshooting

7.1 API Key Rotations

If AI responses begin failing with 401/403 errors, verify the OpenRouter API Key.

  • Update the OPENROUTER_API_KEY in the .env.local file or deployment environment variables.
  • Restart the application server to apply changes.

7.2 Database Connection Issues

If the dashboard fails to load documents or escalate leads:

  • Verify NEXT_PUBLIC_SUPABASE_URL and NEXT_PUBLIC_SUPABASE_ANON_KEY.
  • Ensure the Supabase project is not paused (applicable for free tier Supabase instances).
Important: Never modify the kb_chunks or kb_documents tables directly via the Supabase SQL editor unless performing emergency data migrations. Always use the Admin Dashboard.

8. Emergency Procedures

In the event of a critical failure (e.g., AI generating inappropriate responses, data leak):

  1. Immediately take the application offline by disabling the deployment via the hosting provider dashboard (e.g., Vercel).
  2. Change the ADMIN_PASSWORD.
  3. Rotate the OPENROUTER_API_KEY.
  4. Audit the knowledge base for poisoned or incorrect documents and delete them.
  5. Restore service and monitor closely.
